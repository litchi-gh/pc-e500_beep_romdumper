# 変更履歴

[English](CHANGELOG_en.md)

## 0.3.1（2026-11-06）

### 変更

- アプリと `beepdump` が表示する CSAVE M の命令から、要らないファイル名を外しました。打つ文字が減ります。読み取りは変わらず、名前の付いた録音も読めます。

## 0.3.0（2026-11-06）

### 追加

- **CSAVE M の録音を読めるようにしました。** `CSAVE M &HC0000,&HFFFFF` の 1 行で ROM を鳴らせるので、プログラムを打ち込まずに済みます。本体 256KB は約 22 分です。
  - ブロックごとの検査がないので、1 回の録音で読めたブロックは黄色です。2 回の録音が一致すると緑になります。
  - 実機の PC-E500、PC-E550、PC-1480U、PC-E650、PC-U6000 の録音 8 本で確かめ、誤ったデータは 0 バイトでした。物音の所は読めなかったことにして赤にします。
- アプリの「打ち込み」の欄に CSAVE M を追加しました。打つ命令、手順、色の意味、足りない範囲の命令を表示します。CSAVE M の録音を読むと、自動で切り替わります。
- `beepdump listing --csave` で命令を表示します。`beepdump decode` は CSAVE M の録音も読み、足りない範囲を命令の形で表示します。

### 変更

- アプリの画面の上の欄の並びを変えました。1 行目が機種とボタン、2 行目が打ち込みの方式と言語です。

### 修正

- 表示倍率 150% で画面の一部が崩れるのを直しました。欄の高さとマス目の見出しの高さを、文字の高さと倍率から決めます。
- 読みにくい機械語版の録音の解析が遅いのを直しました（実機の PC-U6000 の録音で 24 分から約 3 分）。音量をならす解析パターンが録音の前後の部屋の雑音を音と取り違え、雑音から学んで全部のブロックを読み直していました。2 つ目以降のパターンは、最初に読めた音の範囲だけを読みます。
- 機械語版で、録音の終わりの雑音に番地を振り、存在しないブロック（`00000` や `40000` など）を「読めなかった」と表示することがあったのを直しました。このブロックが残ると、全部読めても解析が続いていました。

## 0.2.0（2026-11-05）

### 変更

- 打ち込むプログラムを変えました（機械語版は 21 行になりました）。DATA の末尾の数も変わったので、前の版のリストと混ぜないでください。
  - 機械語の中身と音の形式は同じです。前の版のプログラムで録った録音も、そのまま読めます。
- 緑にする条件を厳しくしました。誤ったデータを緑にしないためです。緑だったブロックが、黄や赤になることがあります。
  - BASIC 版で番地を確かめられないブロックは、「読めなかった」にします。反対の票があるときは、多い方が 2 倍を超えないと確かとしません。
  - BASIC 版を標準以外のパターンでしか読めなかったブロックと、サンプリング周波数が 32 kHz 未満の BASIC 版の録音は、検査が通っても黄にします。
  - 機械語版で 1 ブロックしか読めなかったときは、黄にします。
- 内容が食い違ったときの扱いを変えました。
  - パターンの間で食い違ったブロックは、多数決をやめて「読めなかった」にします。
  - 録音の間で食い違ったブロックは、緑でも黄でも保留して赤にします。新しい内容が 2 回以上そろい、ほかのどの内容より多くなったら採ります。
- 同じ録音は 1 回だけ数えます。ファイルの内容で比べるので、名前を変えたコピーも同じ録音と分かります。同じ名前で録り直したファイルは別の録音として読みます。
- 録り直しの範囲は、足りない所の 2 ブロック前から、合わせて 8 ブロック以上にして表示します。BASIC 版の短い録音は読めないことがあるためです。
- `beepdump decode` は、既にある ROM ファイルを上書きしなくなりました。上書きするときは `--force` を付けます。読めなかった録音があったときは、`--force` でも上書きしません。

### 追加

- 機械語の領域を確保せずに `RUN` すると、`POKE LINE FIRST` と表示して止まります。`POKE` の行を実行すれば、打ち込んだプログラムは消えずに続けられます。
- 機械語版で番地を逆に答えたときや、DATA の行が抜けているときは、`NG` と表示して止まります。
- 全部読めたあとで、黄色のブロックを確かめるために録音する範囲を表示します。
- 選んだ機種の ROM の範囲外のブロックを読んだときに、注意を表示します。
- `beepdump decode` に `--force` を追加しました。

### 修正

- 開始番地や終了番地がブロックの途中のときに、正しい範囲を読まないことがあったのを直しました。
- BASIC 版で、終了番地がブロックの先頭のとき、そのブロックを読まなかったのを直しました。
- `.BAS` ファイルの末尾に `0x1A` が付いていたのを直しました。
- 短い録り直しや、物音の入った BASIC 版の録音で、版を取り違えることがあったのを直しました。
- 機械語版で最初の学習に失敗すると、そのあとを読めないことがあったのを直しました。
- BASIC 版で、検査値の音の読み違いから、誤ったデータを緑にすることがあったのを直しました。
- 解析の途中でエラーが起きたときに、読めたブロックまで失っていたのを直しました。何も読めていないときは、残りのパターンを試します。
- 保存に失敗したときに、前の ROM ファイルが壊れないようにしました。
- `beepdump decode` は、書き込めない出力先を解析の前に知らせます。
- アプリで、読めなかった録音をもう一度試せるようにしました。読み取りでエラーが起きても、ボタンが押せなくならないようにしました。
- ffmpeg が失敗したときの報告と、大きな WAV ファイルの読み込みを直しました。

## 0.1.0（2026-11-05）

最初のリリースです。

- ブザーの音で ROM を送るプログラムを 2 種類用意しました。機械語版（約 15 分で 256KB）と、機械語を使わない BASIC 版です。
- 録音から ROM を組み立てるアプリを用意しました。画面のある `BeepDump`（Windows）と、コマンドラインの `beepdump` です。
- 実機の録音で、PC-E500 と PC-U6000 の ROM を読めることを確かめました。
